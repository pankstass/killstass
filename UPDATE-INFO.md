# KILLSTASS v1.15.0 — справочник и запись результатов

Полная поставка: `killstass-v1.15.0.zip`. Faction Rules сгруппированы по фракциям и снабжены локальными эмблемами; Tac Ops разделены по архетипам с цветовой индикацией. Результат сыгранного матча теперь можно отправить зарегистрированному сопернику по его публичному ID. До подтверждения соперником матч не учитывается в статистике. Подробности и происхождение эмблем — `docs/26-v1.15.md`.

## Обновление работающего сервера с 1.14.1

1. Скопируйте архив и сумму: `scp -P 2026 killstass-v1.15.0.zip killstass-v1.15.0.zip.sha256 sslaveh@192.168.1.250:`, затем `su -` и `mv /home/sslaveh/killstass-v1.15.0.zip* /root/`.
2. Выполните `cd /opt/killstass && ./scripts/update.sh /root/killstass-v1.15.0.zip`. При `DeadlineExceeded` используйте `COMPOSE_BAKE=false ./scripts/update.sh /root/killstass-v1.15.0.zip`. Скрипт проверит суммы, сохранит резервную копию, обновит сервисы и выполнит проверки.
3. Проверьте `smoke: ok`, `/api/health`: версия 1.15.0 и 17 миграций. Новая миграция 017 добавляет поле без удаления старых данных; `.env` менять не требуется. Проверьте на двух аккаунтах создание и подтверждение результата.

Откат: `./scripts/update.sh --rollback`. Миграции остаются в базе. При возврате к 1.14.1 не открывайте на редактирование оспоренные записи, созданные в 1.15.0: старый код не различает их и обычные матчи. Отмените их до отката или после повторного обновления.

# KILLSTASS v1.14.1 — исправление загрузки

`killstass-v1.14.1.zip` — полная поставка. Исправлена вероятная причина белого экрана в 1.14.0: при одновременных запросах модулей API мог отвечать 503, а прокси позволял браузеру надолго закэшировать ошибку. Увеличен лимит соединений, ошибки больше не получают длительного кэширования, установка service worker разбита на небольшие группы запросов. Вместо пустого экрана при сбое запуска показываются действия «Обновить» и «Починить»; офлайн-очередь не удаляется. При ошибке открытия страницы доступен переход в Штаб. Подробности — `docs/25-v1.14.1.md`.

## Что включено

Исправлены quoting tmpfs, снятие capability бинарника Caddy при non-root/cap_drop, default_sni для HTTPS по IP. JIT выключен только для app-роли в текущей БД после её создания мигратором; настройка повторяется при update/restore. Ресурсные лимиты остаются 640+384+128 МиБ. Новых схемных миграций нет, 001–004 неизменны.

Документы: `docs/10-developer-handbook.md`, `docs/11-deployment-changelog.md`, `docs/07-verification.md`. Исторический `UPDATE-BASE-SHA256SUMS` относится к базе старого patch v1.1, не используется для проверки v1.1.1: текущий манифест — **SHA256SUMS**.

Нет Docker daemon в среде подготовки: новый ZIP не объявляется проверенным полным контейнерным запуском на ass-srv. Отдельно описаны повторные тесты и факты с работающего сервера. Если ручные исправления уже работают, срочная переустановка не нужна.
