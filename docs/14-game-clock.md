# 14. v1.4.0 — игровые часы

Этап 4 плана приближения к BattleKit. Часы общие для обоих телефонов: время считает сервер по журналу событий, клиент только дорисовывает секунды между обновлениями, поэтому расхождений между устройствами нет.

## Режимы

| Режим | Что считает | Кнопки |
|---|---|---|
| Секундомер | общее время партии | Старт / Пауза / Продолжить / Сброс |
| Шахматные часы | время каждого игрока (вверх) + общее | Старт за игрока, крупная плитка активного игрока = «передать ход», Пауза |
| Обратный отсчёт | остаток лимита каждого игрока (минуты на игрока) | как у шахматных; при исчерпании — красный перерасход «−m:ss», игра не останавливается |

- Часы включаются в идущем матче: панель «Игровые часы» под табло → режим → «Включить часы».
- Первой предлагается кнопка «Старт» за игрока с инициативой в текущем повороте.
- Режим можно сменить только на паузе; смена и «Сброс» обнуляют время (новое событие `configure`).
- «Передать ход» может нажать любой участник (если соперник забыл). Повторное нажатие той же стороны — безопасный повтор без эффекта.
- При «Завершить» запущенные часы автоматически ставятся на паузу; в завершённом матче показывается «Время по часам» (только чтение).
- «Поменять местами» (v1.3) влияет и на порядок плиток.
- Пока часы идут, телефон не гаснет (Screen Wake Lock, только по HTTPS; если браузер не поддерживает — молча игнорируется).

## Почему часы не меняют `matches.version`

Шахматные часы переключаются часто. Если бы каждое нажатие увеличивало версию матча, следующий «+1 VP» соперника падал бы с `version_conflict`. Поэтому:

- команды часов идемпотентны по `request_id`, но без `version`; конфликт решает сама логика (повторный старт/пауза/передача — no-op);
- SSE `/matches/{id}/events` присылает отдельное событие `clock` (номер последнего события часов), клиент запрашивает только `GET /clock` и перерисовывает только панель часов — заметки и формы не сбрасываются;
- интервал проверки SSE сокращён с 3 до 2 с.

## API

| Метод и путь | Права и тело | Ответ |
|---|---|---|
| GET /matches/{uuid}/clock | участник | состояние часов |
| POST /matches/{uuid}/clock | участник, только `active`; `request_id`, `action` configure/start/pause/switch, `mode` stopwatch/chess/countdown (configure), `limit_minutes` 1–600 (countdown), `slot` (start: кто начинает; switch: чья активация закончилась) | 200 `ok`, `changed`, `clock`; 409 `clock_closed`, `clock_running`, `clock_not_configured`, `clock_not_running`, `clock_mode_invalid`, `clock_limit_invalid`, `clock_slot_required` |
| GET /matches/{uuid} | + `clock` | |

Состояние: `mode`, `limit_seconds`, `running`, `started`, `active_slot`, `total_seconds`, `slots[]` (`slot`, `elapsed_seconds`, `remaining_seconds` для countdown), `seq`, `server_now`.

## База данных — 007_match_clock.sql

`match_clock_events(id, match_id, action, mode, limit_seconds, slot, actor_id, server_ts)` — append-only журнал (он же аудит часов: кто и когда нажал). `server_ts = clock_timestamp()` сервера БД; состояние вычисляет `domain.clock_state`. Отдельные записи в `match_audit` для часов не создаются, чтобы не засорять историю изменений счёта. Удаление матча — каскадом.

## Тесты

- `tests/test_domain.py::test_clock_state_modes_and_commands` — свёртка событий во всех режимах, сброс, перерасход, правила команд.
- `tests/test_clock.py` — общие часы двух игроков без изменения `version`, повтор нажатия, идемпотентность, автопауза при завершении и заморозка времени, права (не участник 404, setup/завершённый 409), валидация режима и лимита, hot-seat.
- Браузер (два контекста Chromium 390×844 + 1280×900): матч по приглашению, шахматные часы — старт на телефоне A виден на B через SSE, передача хода, пауза с B видна на A, сохранение CP после команд часов без конфликта версии.

## Не входит

Время в статистике и истории матчей, звуковой сигнал при исчерпании лимита, добавка времени (increment/delay).
