# 13. v1.3.0 — инициатива по поворотам и подсчёт итога

Этап 3 плана приближения к BattleKit. Инварианты v1.1–v1.2 сохранены: сервер считает очки, команды идемпотентны (`request_id`) и версионированы (`version`), каждое изменение пишется в аудит, итог выводится только из первичных записей.

## Пользовательские сценарии

### 1. Инициатива

- В TP1 инициатива берётся из общей настройки матча (`matches.initiative`).
- При переходе на TP2+ без записи панель поворота показывает выделенный блок «Кто получил инициативу?» с кнопками игроков. Блок не модальный: он не мешает вести счёт и не теряется при синхронизации с соперником.
- Отметить или исправить может любой участник (в hot-seat — владелец устройства). Исправление — «Изменить» под строкой «Инициатива: …». Каждое изменение пишется в аудит (`initiative`, было/стало).
- Кнопки поворотов получают метку `★` + первая буква имени; у игрока с инициативой на табло — бейдж «★ Инициатива»; в таблице «Счёт» — столбец «Инициатива».

### 2. «Подсчитать итог»

- Кнопка доступна только в последнем повороте активного матча; раньше остаётся обычное «Завершить» (досрочное завершение не запрещено).
- Таблица: Crit, Tac, Kill (с отметкой «+1» за больше выведенных из строя), «Осн.» — бонус основной операции, «Всего».
- Тайна основной операции соблюдается: в общем матче вы видите свой бонус и выбор, у соперника — `+?` и «Всего» вида `N + ?`. В hot-seat бонусы обоих скрыты («в конце»), потому что экран общий.
- Если основная операция кем-то не зафиксирована, показывается предупреждение: её бонус будет +0.
- Подсчёт не меняет данные. После любого изменения матча (новая версия) таблица скрывается — нажмите «Пересчитать».

### 3. «Поменять местами»

Только на этом устройстве (localStorage `killstass-swap-<id матча>`): порядок игроков на табло, панелях hot-seat, в подсчёте итога и таблице счёта. На сервер и второму игроку не влияет.

### 4. CP между поворотами

Если в текущем повороте CP ещё не сохранены, показывается последнее известное значение с подписью «с прошлого поворота». Автоматически ничего не записывается: при нажатии ± сохраняется новое значение уже для текущего поворота. Заметки не переносятся.

## API

| Метод и путь | Права и тело | Ответ |
|---|---|---|
| POST /matches/{uuid}/initiative | участник; `request_id`, `version`, `turning_point` (≤ current_turn), `slot` 1/2; только `active` | 200; 409 `initiative_closed` / `version_conflict` |
| GET /matches/{uuid}/preview | участник; только `active` и `current_turn = turns` | 200 `scoring_mode`, `ready`, `players[]`; 409 `preview_closed` |
| GET /matches/{uuid} | + `initiatives[]` (`turning_point`, `slot`) | |

`players[]` в preview: `slot`, `display_name`, `crit`, `tac`, `grade`, `kill`, `kill_bonus`, `base`, `primary_committed`; для своего слота ещё `primary_op`, `primary_bonus`, `vp`. Для соперника (и гостя hot-seat) эти три поля — `null`. Формула совпадает с `player_totals` после завершения (`domain.final_totals`, тест сверяет с фактическим итогом).

## База данных — 006_initiative.sql

`turning_point_initiative(match_id, turning_point, slot, decided_by, created_at)`, PK `(match_id, turning_point)`, `slot` 1/2, удаление матча каскадом. Миграция append-only, 001–005 не изменены. Права app-роли выдаёт мигратор.
