# 12. v1.2.0 — быстрый старт и игра на одном устройстве

Первый шаг плана приближения к BattleKit. Цель — начать матч за несколько касаний, не ломая инварианты v1.1: сервер считает очки, команды идемпотентны и версионированы, каждое изменение пишется в аудит, итог выводится только из первичных записей.

## Пользовательские сценарии

### 1. Пригласить соперника по коду (дружба не нужна)

1. «Новая игра» → «Пригласить соперника» → «Создать код приглашения».
2. Создаётся матч `kind='friend'` в `setup`: слот 1 — создатель, слот 2 пуст. На экране матча показаны код из 6 символов (алфавит без 0/O/1/I), ссылка `https://<host>/#join/<КОД>`, «Копировать ссылку», «Поделиться» (Web Share API, если есть) и «Новый код».
3. Соперник открывает ссылку. Без сессии он сразу видит форму регистрации с баннером приглашения. Имя необязательно, по умолчанию — логин. После регистрации или входа он автоматически занимает слот 2 и попадает на экран настройки.
4. Дальше обычный общий матч v1.1: каждый ведёт свой счёт, `finish` → подтверждение соперником.

Код можно ввести вручную на главной («Присоединиться по коду») или на экране «Новая игра».

### 2. На одном устройстве (hot-seat)

1. «Новая игра» → «На одном устройстве», имя гостя.
2. Создаётся матч `kind='hotseat'`: слот 1 — владелец, слот 2 — запись `guest_opponents`.
3. Владелец сохраняет общие настройки и свои поля, затем передаёт устройство гостю для блока «Тайная настройка игрока» (число оперативников, состав, основная цель, Tac Op). Сохранённый выбор гостя не возвращается в API владельцу: виден только признак `secret_set`.
4. В игре обе панели счёта на одном экране. Фиксация основной цели в TP1 делается отдельно для каждого игрока. На общем табло не показываются основная цель и неоткрытая Tac Op обоих игроков. Владелец может подсмотреть свою карту под переключателем.
5. «Завершить» сразу переводит матч в `unconfirmed` и блокирует изменения. Подтверждения и спора нет. Результат учитывается только у владельца, как гостевая быстрая запись; бонус основной цели и +1 за больший Kill grade начисляются.

### 3. Отмена

Создатель может отменить матч в `setup` (`action='cancel'`). Открытый код при этом удаляется.

## API

| Метод и путь | Права и тело | Ответ |
|---|---|---|
| `POST /api/matches` | сессия; `request_id`, `kind` friend/hotseat, `edition`, `mission_id?`, `guest_name?` (hotseat). Не более `MAX_OPEN_SETUPS` (10) матчей в `setup` на аккаунт | 201 `id`; 429 `too_many_open_matches` |
| `POST /api/matches/{id}/invite` | создатель friend-матча в `setup` с пустым слотом 2; `request_id`. Старый открытый код заменяется, TTL `INVITE_TTL_HOURS` (12) | 201 `code`, `expires_at`; 409 `invite_not_allowed` / `match_full` |
| `POST /api/invites/{code}/join` | сессия; `request_id`. Лимит 20 попыток / 15 мин / IP. Регистр кода не важен. Повтор тем же пользователем возвращает тот же матч | 200 `match_id`; 404 `invite_invalid`; 410 `invite_expired` / `invite_used`; 409 `invite_own_match` / `match_full`; 403 `blocked` |
| `PUT /api/matches/{id}/player-setup` | участник в `setup`; `request_id`, `version`, `slot`, `roster`, `operative_count`, `primary_op?`, `tac_op_id?`, `aspect_counts`. Тайный выбор применяется только для `approved2025` | 200; 403 `slot_forbidden` |
| `POST /api/matches/{id}/scores`, `/kills`, `/primary`, `/reveal-tac` | новое необязательное поле `slot` | как раньше; 403 `slot_forbidden` |
| `POST /api/matches/{id}/actions` | новое действие `cancel` (создатель, `setup`). В hot-seat `finish` → `unconfirmed`; confirm/dispute/reopen → 409 | |
| `GET /api/matches/{id}` | новое: `invite` (только создателю в `setup`), `players[].secret_set` | |
| `GET /api/history`, `/stats`, `/export` | фильтр `kind` принимает `hotseat` | |
| `POST /api/auth/register` | `display_name` необязателен, по умолчанию логин | |

### Правило записи в чужой слот

`domain.slot_allowed`: свой слот разрешён всегда. Чужой — только создателю hot-seat матча и только если в слоте нет зарегистрированного пользователя (гостевой слот). В friend-матчах, включая созданные по коду, поведение v1.1 не изменилось.

## База данных — `005_invites_hotseat.sql`

- `matches.kind` допускает `hotseat`.
- `match_invites(code PK, match_id, created_by, expires_at, used_by, used_at, created_at)`; частичный уникальный индекс — не более одного открытого кода на матч.
- `player_totals`: бонусы конца боя считаются и для `unconfirmed` (для legacy-гостевых записей итог по-прежнему `raw_vp`, поэтому старые результаты не меняются).
- `player_results`: `hotseat` + `unconfirmed` учитывается только у `created_by`, как `guest`.
- Права app-роли выдаёт существующий `db/migrate.sh` (GRANT ON ALL TABLES).
- Удаление аккаунта удаляет и hot-seat матчи владельца.

## Безопасность и ограничения

- Код — короткий одноразовый секрет присоединения, а не учётные данные: он лишь заполняет пустой слот 2 матча в `setup` для уже аутентифицированного аккаунта. Перебор ограничен rate limit и TTL. Блокировка в любую сторону запрещает вход.
- Тайный выбор гостя скрыт от API владельца до конца матча; аудит хранит только факт изменения. Защита от подглядывания на общем экране — организационная (кнопки «передайте устройство»).
- QR-код не реализован: нужен локальный генератор без CDN. Пока есть ссылка, «Копировать» и Web Share API.
- Регистрированный соперник в hot-seat (подтверждение со своего аккаунта) отложен: открытый вопрос плана.
- Офлайн-режима по-прежнему нет: hot-seat требует LAN и API.
