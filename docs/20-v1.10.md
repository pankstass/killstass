# 20. v1.10.0 — офлайн-табло, игровые вечера, сезоны и достижения, ТВ, схема килзоны, домен и удалённый доступ

Сводка выпуска: что появилось у игроков, у администратора и у оператора сервера. API и БД — в конце документа; порядок обновления — `UPDATE-INFO.md`.

## Для игроков

### Табло без сети (офлайн-режим)

Сервис-воркер (`web/sw.js`, адрес `/sw.js`) при первом открытии сохраняет оболочку приложения этой версии, а ответы API — как «последнюю копию». Если Wi-Fi пропал посреди партии:

- открытое табло продолжает работать: очки, CP, убийства, повороты, трекер и часы меняются сразу, команды ставятся в очередь (на устройстве, по игроку) — плашка вверху «Нет связи · в очереди N»;
- когда сервер снова отвечает, очередь отправляется по порядку. Уже отправленная команда повторяется с тем же `request_id` и версией (сервер не применит её дважды), ещё не отправленная получает текущую версию матча; при настоящем конфликте — обычный диалог `version_conflict`;
- нажатия часов в офлайне сохраняют своё время (`at`): сервер пересчитывает часы так, как будто нажатие дошло вовремя (не раньше последнего события часов, не позже «сейчас» и не больше 6 часов назад);
- без сети можно открыть табло и страницы, которые уже открывались; новые матчи, вход и регистрация требуют сервера.

Сервис-воркеры работают только на доверенном HTTPS (или `localhost`). По адресу `https://192.168.1.250` с сертификатом внутреннего CA Caddy телефоны их обычно не включают — офлайн-режим и push заработают на домене с сертификатом Let's Encrypt (см. ниже). Без них приложение работает, как в 1.9.

### Звук и вибрация

Профиль → «Звук и вибрация» (настройки — в этом браузере): сигнал «Ваш ход» (шахматные часы перешли к вам), сигнал, когда соперник подтвердил или оспорил результат, достижения и новости клуба; отдельно — звук и вибрация, кнопка «Проверить сигнал». Тона синтезируются Web Audio (без звуковых файлов); вибрация — только в браузерах Android; звук браузеры разрешают после первого касания страницы. События приходят через общий поток `/api/events` на любой странице приложения.

### Страница игрока и аватар

- `#player/<ID>` (ссылка с имени в друзьях, матчах, таблицах): аватар, девиз, любимая команда, «в клубе с», статистика, место в текущем сезоне, достижения, последние результаты, личные встречи с вами, кнопка дружбы.
- Профиль → «Страница игрока»: аватар (PNG/JPEG/WebP; браузер обрезает до квадрата 256×256 и перекодирует — на сервер уходит копия без EXIF, до 192 КБ), девиз до 140 символов, любимая команда, «Скрыть мою страницу»: скрытую видят только друзья и администраторы, на ТВ и в таблицах сезона вместо имени — «Игрок».

### Сезоны рейтинга и достижения

- **Сезон** — диапазон дат (по Москве) со своими K и стартовым рейтингом, его создаёт администратор. Таблица сезона — общая для клуба: каждый подтверждённый дружеский матч двух зарегистрированных игроков в этих датах, по порядку игр. «Статистика» → выбор сезона (`#season-pick`): место, рейтинг, игры, победы/ничьи/поражения. Elo среди друзей из 1.9 остаётся.
- **Достижения** — правило и порог, при желании только в одном сезоне. Встроенные: «Первая победа», «10 матчей», «Камбэк» (победа после отставания на 3 ПО и больше после одного из поворотов); администратор добавляет свои из правил: матчи, победы, серия побед, камбэк, крупная победа, разные соперники, разные команды, победы в турнирах, посещённые вечера. Выдаются при подтверждении матча (hot-seat — при завершении, быстрая запись — при сохранении), по итогам турнира и при открытии страницы игрока (молча — для результатов, записанных до появления достижения). Новое достижение — уведомление со звуком.

### Игровые вечера

Пункт меню «Вечера» (`#nights`): любой игрок назначает вечер — название, начало и конец, место, заметки, лимит мест (2–64, необязательно), до 10 запланированных на организатора.

- Ответы «Приду / Может быть / Не приду» с командой и комментарием; при заполненном лимите «Приду» — 409 `night_full`. В списке: «Придут: N/лимит · Может быть: M».
- **Пары**: организатор (или администратор) нажимает «Сгенерировать пары» — пришедшие упорядочиваются по рейтингу текущего сезона (без сезона — Elo клуба), соседи играют друг с другом, повторы с прошлых вечеров избегаются, нечётному — bye; пары можно поправить, затем «Опубликовать» — игрокам приходит уведомление. Игрок пары открывает «Матч» за своим столом — дружеский матч с соперником.
- **Календарь**: `.ics` одного вечера («В календарь (.ics)») и личная подписка на все вечера клуба (ссылка показывается один раз, в БД — только хэш; можно заменить или отключить). Подписка работает без входа, но только там, где виден сервер (LAN или Tailscale).
- Изменение и отмена вечера рассылают уведомления ответившим.

### Схема килзоны

Пункт меню «Схемы» (`#maps`), схема — `#map/<id>`; схему матча открывает кнопка «Схема» на табло. Вид сверху в дюймах (по умолчанию 30″ × 22″, 6–60″): оперативники обеих сторон, цели, маркеры, укрытия (тяжёлое, лёгкое, Vantage, стена), стрелки. Кадр 0 — расстановка, кадр N — конец поворота N (до 12); «Воспроизвести» показывает партию по кадрам, к каждому кадру — заметка до 500 символов.

- **Схема матча** — одна на матч, её видят и правят оба игрока, изменения приходят вживую (событие `board`); оперативники подставляются из трекера или по числу оперативников. **Свободная схема** — личная (до 50).
- Правка: перетаскивание, клавиатура (стрелки двигают выбранный жетон, Delete удаляет), свойства жетона, автосохранение кадра целиком с версией (при одновременной правке — `version_conflict` и перечитывание). «PNG» скачивает картинку кадра.

### Экран ТВ

`#tv/<ключ>` — для телевизора или проектора клуба, без входа: живые табло (счёт, поворот, часы — тикают локально), таблица и пары турнира, топ-10 сезона, ближайший вечер, последние результаты. Обновляется каждые 5 секунд, крупный шрифт для экрана. Ссылку создаёт и удаляет администратор; скрытые игроки — без имени.

### Сброс пароля

На странице входа — «Есть код сброса пароля»: логин или e-mail, одноразовый код вида `ABCD-EFGH` и новый пароль. Код выдаёт администратор (#admin) или оператор сервера, он действует 60 минут (`RESET_TTL_MINUTES`) и 5 попыток; после смены пароля все прежние сессии аккаунта завершаются, а игрок сразу входит с новым паролем.

### Push-уведомления

Профиль → «Push-уведомления» (если оператор включил их): вызовы и друзья, действия соперника в матче, подтверждение результата, турниры, вечера, достижения — даже когда вкладка закрыта. «Включить push» (на этом устройстве), «Проверка push-уведомлений». Нужен доверенный HTTPS (домен и Let's Encrypt); на iPhone — iOS 16.4+ и приложение, добавленное на экран «Домой».

## Для администратора (`#admin`)

- **Сброс пароля**: в поиске пользователей — «Сбросить пароль» → код и срок действия; код показывается один раз, передайте его игроку лично. Пароль другого администратора сбрасывает только оператор (`./scripts/admin.sh password LOGIN`).
- **Сезоны рейтинга**: название, даты, K (4–64), стартовый рейтинг (100–3000); сезоны не пересекаются (409 `season_overlap`); сезон с привязанными достижениями не удаляется (409 `season_in_use`).
- **Достижения**: код, правило, порог, названия и описания RU/EN, значок, сезон, порядок, «Активно»; встроенные можно настраивать и выключать, но не удалять. «Пересчитать» выдаёт достижения по всем уже записанным результатам.
- **Экраны ТВ**: подпись и турнир (или «последний активный») → ссылка `#tv/<ключ>`; «последний показ»; удаление сразу отзывает ссылку.

## Для оператора сервера

### Обновление из архива: `update.sh killstass-vX.zip`

```sh
su -
cd /opt/killstass
./scripts/update.sh /root/killstass-v1.10.0.zip     # рядом лежит killstass-v1.10.0.zip.sha256
./scripts/update.sh --rollback                        # вернуть предыдущий выпуск
```

1. Проверки: SHA-256 архива (файл `.sha256` рядом или `--sha256 HEX`), распаковка во временный каталог (`unzip`, иначе `bsdtar`, `python3` или Python из образа api), `sha256sum -c` по `SHA256SUMS`, список файлов архива совпадает со списком сумм, нет символических ссылок и путей с `..`; версия новее установленной (та же или старее — только с `--force`). Ошибка на этом шаге ничего не меняет.
2. Сохранение: дамп БД (`backup.sh`), архив текущего кода и копия `.env` в `/var/backups/killstass` (хранятся 5 последних выпусков), образы `killstass-{api,db,proxy}:local` → `:prev`, файл состояния `last-update`.
3. Раскладка: файлы прежнего выпуска, которых нет в новом, удаляются; остальные заменяются (новый inode — работающий скрипт не портится); права 644/755, владелец — как у `VERSION`. `.env`, `local/`, `backups/` и посторонние файлы не трогаются.
4. Обычный порядок 1.9: сборка, `smoke.sh --pre`, остановка proxy/api, db, миграции, запуск, проверки после запуска. Если что-то не прошло — **автоматический откат**: код, `.env` и образы `:prev`, `docker compose up -d --wait --remove-orphans`, мигратор прежней версии (права роли), проверка health. БД не откатывается: миграции только добавляют таблицы; для проблем с данными скрипт печатает команду `restore.sh` с дампом.

Без аргументов `update.sh` работает, как раньше (файлы уже разложены вручную). `smoke.sh --post` дополнительно проверяет `/sw.js` и иконку, предупреждает (без отката), если на домене нет доверенного сертификата или не запущены `pushworker`/`tailscale` включённых профилей. Исправлена ошибка 1.9.0: `smoke.sh --post` искал `<meta … content="1.9.0">`, а страница пишет `<meta … />` — проверка падала на рабочем сервере.

### Домен killstass.su

```sh
./scripts/domain.sh set killstass.su     # KS_DOMAIN, APP_ORIGIN (IP и домен), перезапуск api и proxy
./scripts/domain.sh status               # настройки, DNS, сертификат
./scripts/domain.sh unset
```

Домен должен разрешаться в `192.168.1.250` — A-запись у регистратора (адрес частный: снаружи сайт всё равно недоступен) или запись в DNS роутера. Многие роутеры отбрасывают ответы DNS с частными адресами (защита от DNS rebinding) — тогда добавьте исключение для домена или локальную запись в роутере. Сайт продолжает работать и по `https://192.168.1.250`; сессии у адресов разные (cookie привязана к хосту), `APP_ORIGIN` теперь принимает список.

Caddy (`proxy/Caddyfile`) обслуживает домен отдельным сайтом: сертификат внутреннего CA (`KS_TLS_MODE=internal`) до получения Let's Encrypt, затем файлы из `local/acme/certificates` (`KS_TLS_MODE=files`, том `/certs` только для чтения). HTTP 80 перенаправляет на тот адрес, по которому пришли.

### Сертификат Let's Encrypt (DNS-01)

Сервер не открыт в интернет, поэтому проверка — через TXT-запись DNS: `scripts/cert.sh` запускает [lego](https://go-acme.github.io/lego/) в контейнере (`goacme/lego:v4.29.0`, без прав, read-only), lego создаёт запись через API DNS-хостинга, получает сертификат и удаляет запись.

1. `.env`: `ACME_EMAIL=…`, `ACME_DNS_PROVIDER=…` — код провайдера lego (`regru`, `nicru`, `beget`, `timewebcloud`, `selectelv2`, `yandex360`, `yandexcloud`, `cloudflare`, …; переменные — `docker run --rm goacme/lego:v4.29.0 dnshelp -c regru`).
2. `local/acme.env` (0600): ключи API провайдера, например `REGRU_USERNAME=…` и `REGRU_PASSWORD=…`.
3. `./scripts/cert.sh issue` → `KS_TLS_MODE=files`, перезапуск proxy. Проверка: `./scripts/cert.sh status`.
4. Продление: `systemd/killstass-cert.timer` (дважды в день, `cert.sh renew` продлевает за треть срока и перезапускает proxy только при новом сертификате):
   `cp systemd/killstass-cert.* /etc/systemd/system/ && systemctl daemon-reload && systemctl enable --now killstass-cert.timer`.

Caddy сам к ACME не обращается. Для проверки без лимитов — `ACME_SERVER=https://acme-staging-v02.api.letsencrypt.org/directory`. У многих провайдеров доступ к API включается отдельно (у reg.ru — пароль API и разрешённые IP-адреса: внешний адрес вашего подключения). Если записи DNS провайдера обновляются медленно и lego не дожидается TXT-записи, добавьте в `local/acme.env` `<КОД>_PROPAGATION_TIMEOUT=900`, например `REGRU_PROPAGATION_TIMEOUT=900`.

### Доступ извне через Tailscale

```sh
./scripts/tailscale.sh enable tskey-auth-…   # ключ: login.tailscale.com → Settings → Keys
./scripts/tailscale.sh status
./scripts/tailscale.sh disable
```

Контейнер `tailscale` (профиль compose, сеть хоста, `/dev/net/tun`) — subnet router только для адреса сервера `192.168.1.250/32`, без проброса портов на роутере. Скрипт включает профиль, добавляет сеть tailnet `100.64.0.0/10` в `KS_ALLOW_NETS` (её пропускают Caddy и `firewall.sh`), поднимает контейнер и после входа удаляет ключ из `.env` (состояние — в `local/tailscale`). В консоли Tailscale один раз подтвердите маршрут (Machines → killstass → Edit route settings → 192.168.1.250/32). На телефонах — приложение Tailscale с тем же аккаунтом: `https://killstass.su` и `https://192.168.1.250` открываются из любой сети. `--snat-subnet-routes=false` сохраняет адрес клиента 100.x для проверки сети. `TS_FORCE_NOISE_443=true` — связь с сервером координации только через HTTPS 443: на ass-srv через порт 80 (быстрый путь по умолчанию) проходили вход и первая карта сети, а затем поток замирал, вероятно, на прозрачном прокси провайдера (`map response long-poll timed out!` каждые 2 минуты, узел `offline`, см. D-10 в `11-deployment-changelog.md`).

### Web Push

```sh
./scripts/push.sh enable mailto:admin@example.org   # PUSH_ENABLED=1, профиль push, контейнер pushworker
./scripts/push.sh status                           # подписки, очередь, последняя доставка
./scripts/push.sh test LOGIN                       # проверочное уведомление игроку
./scripts/push.sh disable
```

API выхода в интернет по-прежнему не имеет: уведомления пишутся в очередь `push_outbox`, отправляет их отдельный `pushworker` (тот же образ, сети backend + edge, без портов, read-only) — шифрование RFC 8291 (aes128gcm) и VAPID RFC 8292 (ключи создаются при первом запуске и хранятся в `app_settings`). Адреса подписок — только известные push-службы браузеров (`PUSH_ALLOWED_HOSTS`); без интернета сообщения ждут до часа (`PUSH_MAX_AGE_SECONDS`), затем отбрасываются. Через прокси — `PUSH_HTTPS_PROXY`.

### Прочее

- `./scripts/admin.sh password LOGIN` — код сброса пароля в консоли.
- `scripts/firewall.sh` берёт сети из `KS_ALLOW_NETS` (`.env`) и `BIND_IP`; правила прежние (свои цепочка/таблица), разрешённых сетей теперь несколько.
- `scripts/lib.sh` — общие функции скриптов (правка `.env` атомарной заменой с режимом 0600, профили compose, проверки сетей и доменов).
- `.env.example` — новые необязательные настройки (их пишут скрипты), `RESET_TTL_MINUTES=60`.
- Тестовый образ (`tests/Dockerfile`) копирует весь проект без `.env` и `local/` (`.dockerignore`): тесты 1.9 читали `scripts/`, `README.md`, `package.json`, которых в образе не было.

## API

Изменяющие запросы — с `request_id` и CSRF, как раньше.

| Метод и путь | Права | Ответ |
|---|---|---|
| POST /admin/users/{public_id}/password-reset | администратор | 201 `{code, expires_at, ttl_minutes, login, display_name}`; 403 `reset_admin_forbidden`; 404 `user_not_found` |
