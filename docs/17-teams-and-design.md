# 17. Справочник команд и новый дизайн (v1.7.0)

## Справочник команд и оперативников

Раздел **«Команды»** в меню (`#teams`): все kill team с архетипами и числом оперативников, поиск по названию/архетипу. Страница команды (`#teams/{slug}`) — вкладки:

- **Оперативники** — датакарты: APL / MOVE / SAVE / WOUNDS, оружие (ATK / HIT / DMG, особые правила, значок стрельбы или ближнего боя), способности, уникальные действия, ключевые слова, размер подставки, ссылка на изображение исходной карты (открывается на GitHub, в приложение не встраивается). Поиск по имени, оружию и ключевому слову.
- **Правила фракции**, **Ploys** (strategy и firefight), **Снаряжение**, **Состав** (правила набора команды).

На табло матча название команды игрока — ссылка на её датакарты (если команда есть в справочнике). Внизу каждой страницы указаны источники с коммитом и датой загрузки.

Тексты правил показываются **на английском**, как в источниках; интерфейс вокруг них переведён на RU/EN.

### Источники данных

| Источник | Что берём | Как |
|---|---|---|
| [Wen-Qualtu/kt-datacards](https://github.com/Wen-Qualtu/kt-datacards) | `output/{team}/data/{team}-team-data.json`: датакарты, оружие, способности, действия, ploys, снаряжение, правила фракции, состав; ссылки на `cards/datacards/*-front.jpg` | только нужные raw-файлы по закреплённому коммиту (репозиторий ~6 ГБ целиком не скачивается) |
| [BSData/wh40k-killteam](https://github.com/BSData/wh40k-killteam) | `2024 - *.cat` + `2024 - Kill Team.gst`: профили Operative (APL, Move, Save, Wounds) и Weapons (⌖/⚔) | сверка характеристик, тип оружия (дальнее/ближнее), запасной источник для команд, которых нет в kt-datacards (сейчас Strike Force Variel — только характеристики, оружие и способности, без ploys и правил фракции) |

При расхождении характеристик между источниками показывается значение kt-datacards, плитка подсвечивается оранжевым, под ней — «В BSData иначе: …». На момент подготовки (kt-datacards `042e924`, BSData `30c48ce`) — 49 команд, 460 оперативников, 7 расхождений (Fellgor Ravagers save, Murderwing Chaos Lord и Ratling Bomber wounds — похоже на ошибки распознавания PDF в kt-datacards).

**Права.** У обоих репозиториев нет лицензии; игровые тексты принадлежат Games Workshop. Поэтому данные **не входят в ZIP-поставку KILLSTASS**: администратор сервера сам загружает их для личного некоммерческого использования в своей LAN. При сомнениях сверяйтесь с актуальными публикациями GW (errata/балансные обновления в источниках могут запаздывать).

### Загрузка и обновление (администратор)

```sh
cd /opt/killstass
./scripts/import-teams.sh             # скачать последнюю версию с GitHub и загрузить (≈10–20 с)
./scripts/import-teams.sh --status    # что загружено сейчас
SAVE_BUNDLE=/root/teams-bundle.json ./scripts/import-teams.sh   # то же + сохранить файл
./scripts/import-teams.sh /root/teams-bundle.json               # загрузить готовый файл без интернета
KTD_REF=<sha> BSDATA_REF=<sha> ./scripts/import-teams.sh        # закрепить версии источников
```

Как это устроено:

1. Скачивание выполняется **во временном контейнере** `killstass-api:local` в сети Docker по умолчанию (`--rm --read-only --cap-drop ALL`). Сам сервис `api` по-прежнему без выхода в интернет (сеть `backend` internal). Нужен доступ сервера к `api.github.com` и `raw.githubusercontent.com`; без него используйте готовый файл.
2. Файл-пакет `killstass-teams/1` (JSON, ≤25 МБ) проверяется в контейнере `api` (`python -m api.teamdata sql`) и превращается в SQL.
3. SQL применяет **владелец БД** через локальный сокет контейнера `db` одной транзакцией. Роль приложения `killstass_app` может только читать `team_data` (как и `catalogs`).
4. Повторный импорт обновляет команды по `slug`; отсутствующие в новом пакете скрываются (`active=false`), история импортов — в `team_data_imports`. Ссылки на матчи не затрагиваются: справочник не связан со счётом.
5. Команда связывается с записью `catalogs` (kind=team, edition 2024) по коду `…-team-{slug}` — так на табло появляется ссылка, а в списке показывается локализованное название.

Если справочник не загружен, страница «Команды» показывает подсказку с командой импорта; остальные функции работают как раньше.

### API и БД

- `GET /api/teams` (сессия) → `{teams:[{slug,name,catalog_id,archetypes,operatives,imported_at}], import:{imported_at,built_at,sources,teams,operatives}|null}`.
- `GET /api/teams/{slug}` (сессия) → `{slug,name,catalog_id,data,sources,imported_at}`; `ETag` = SHA-256 содержимого, `If-None-Match` → 304; неизвестный — 404 `team_not_found`.
- Миграция `009_team_data.sql` (append-only): `team_data`, `team_data_imports`. Health ожидает 9 миграций.
- Ссылки на изображения карт допускаются только `https://` (проверка при импорте и в клиенте).

## Новый дизайн

Минималистичный светлый/тёмный интерфейс в духе современных справочников Kill Team (BattleKit): тёмная верхняя панель с логотипом и оранжевой линией, светлый фон, белые карточки со скруглением 14 px и мягкой тенью, узкие заголовки (PT Sans Narrow), системный шрифт для текста, один оранжевый акцент. Изображения и оформление BattleKit/GW не копировались.

- Тема по умолчанию — как в системе (`prefers-color-scheme`), переключатель ◐ сохраняет выбор в браузере.
- Цвета игроков: игрок 1 — красный, игрок 2 — синий (полоса сверху карточки, номер и счёт лидера); лидер обведён своим цветом.
- Повороты — сегментированный переключатель; бейджи — «таблетки»; цифры счёта, метрик, часов и кубиков — узкий шрифт с табличными цифрами.
- Desktop: фиксированная верхняя панель 56 px и боковое меню 220 px (на планшете 200 px). Телефон (≤720 px): верхняя панель 52 px, нижнее меню из 6 пунктов.
- Убраны: сетка на фоне, срезанные углы кнопок, «тактические» метки панелей, штриховка у заголовков, декоративные подписи вида `KILLSTASS / …` над заголовками.
- Классы разметки сохранены; панель «Последовательность игры» встаёт под верхнюю панель.

Токены и компоненты — `04-style.md`.
