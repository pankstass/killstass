# 1. Допущения и стек

1. Самостоятельный локальный проект **killstass**, не официальный продукт Games Workshop.
2. Целевая платформа — linux/amd64, Ivy Bridge; AVX2 не требуется Python, PostgreSQL, Caddy.
3. FastAPI + psycopg: один процесс без ORM-кэша, пул 1–5 соединений, параметризованный SQL.
4. PostgreSQL 16 Alpine: транзакции, UTC/timestamptz, представление результатов и SQL-агрегаты.
5. HTML/CSS + vanilla JS: нет Node.js в production, npm-зависимостей, CDN или frontend-сборки.
6. Caddy internal: частный CA, HTTPS, HTTP→HTTPS; на клиентах требуется доверие к CA.
7. Только IPv4 LAN 192.168.1.0/24, привязка портов к 192.168.1.250, без публикации БД/API.
8. Лимиты стека 640 + 384 + 128 = **1152 МиБ**, CPU 1.25 + 1.0 + 0.5; это потолки, не измерение RSS.
9. По умолчанию редакция 2024, 4 поворота; 2021 также поддерживается как параметр.
10. v1.1: проверенный снимок Kill Team 3 / Approved Ops 2025 (edition=2024) с метаданными источников; 48 активных команд, 9 Crit Ops, 11 активных из 12 Tac Ops, 30 схем killzones и Game Sequence в БД. Неподтверждённые/конфликтные записи неактивны; edition=2021 сохранена для истории. Детали — docs/09-catalog-import.md.
11. Crit/Tac VP вводятся вручную по проверенным карточкам с лимитами поворота и 6 VP за направление. Kill grade, финальный +1 и бонус основной цели вычисляются из первичных записей БД. Старые матчи сохраняют режим legacy, гостевые — уже итоговый счёт без повторного бонуса.
12. CP — остаток на выбранном повороте, **не сумма за матч**. Автоматическое начисление по правилам не предполагается.
13. Подтверждённый общий матч и собственная гостевая запись входят в статистику; спорный — нет.
14. Гость пока не привязывается к аккаунту; поле linked_user_id — только задел, не работающая функция импорта.
15. По умолчанию Approved Ops 2025, карточки/Companion August 2026 и Core Rules June 2026 по метаданным открытых страниц на 26.10.2026. При смене пакета/баланса нужен новый проверенный импорт. Неясные условия Sweep & Clear и архетипы Strike Force Variel требуют ручной сверки, не догадок. Предварительная основная цель в setup — лишь подготовка, фиксация происходит тайно в Gambit TP1.

Дизайн и SVG созданы для проекта. В v1.1 прочитаны публичные страницы BattleKit/Wahapedia для фактов справочников. Дизайн и код этих сайтов не копируются. Карточки представлены собственным кратким пересказом; полные правила команд — только ссылки. Инструмент импорта не включён в production API image.

## Эксплуатационное дополнение v1.1.1

- tmpfs задаётся одной цитированной строкой: запятые вне кавычек разделяли YAML-массив на неверные пути.
- Caddy сохраняет non-root/cap_drop/no-new-privileges; file capability бинарника снимается в Dockerfile, внутренние порты высокие. Для клиентов без SNI задан глобальный default_sni APP_HOST.
- JIT выключен для killstass_app только в текущей БД. Настройка идемпотентно применяется db/migrate.sh после создания роли, не изменением 001–004 и не глобальным параметром PostgreSQL. Перезапуск API обновляет pool-соединения.
- Лимиты 640+384+128 МиБ сохранены. OOM Caddy не доказан; улучшение после role-level JIT подтверждено оператором без числового замера.
- Обоснование/границы свидетельств: docs/10-developer-handbook.md и docs/11-deployment-changelog.md.
