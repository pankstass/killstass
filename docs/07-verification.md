- SHA-256 001_initial.sql и 002_seed.sql совпадают с поставкой v1.0; проверяются автоматическим тестом. 002 bootstrap читает копию прежнего seed из db/legacy-seed.json; свежая установка не пытается загрузить новые kind до расширения схемы.
- **32 passed, 1 warning**, 4.48 s на стенде: Python 3.13, закреплённые FastAPI/psycopg/pytest/httpx; production Dockerfile по-прежнему Python 3.12. Warning — deprecated alias anyio в Starlette TestClient, не ошибка приложения. Это не замер производительности ass-srv.
- Тест обновления: создан старый подтверждённый матч с результатом 9:6 (выше новых component caps), снимок player_results сравнен побайтно по значениям до/после миграции и повторной 004. Итог остался 9:6, не 6:6 и без primary-бонуса. Каталог не удалён, ID сохранён, active=false.

- Доменные и интеграционные проверки: ceil бонуса 0..6, ошибочные границы, Kill grade/возвращение врага, cap карточки/поворота и общий cap 6, условные архетипы Blades, запрет активировать непроверенные данные, frozen caps после обновления карточки, auth/ETag/304 справки и отказ без сессии.

## Приёмка на ass-srv с двух телефонов

1. Для текущей v1.1.1 использовать полный архив: сохранить предобновленческий дамп/файлы, сравнить локальные правки, проверить SHA256SUMS, выполнить scripts/update.sh. Старый patch v1.1 требовал полной v1.0; новый полный ZIP этого не требует. Не удалять volumes, не менять .env/SSH2026/firewall. Проверить три healthy и `/api/health`.
2. Доверить публичный CA на обоих телефонах, открыть один и тот же HTTPS origin в домашнем Wi-Fi. Войти двумя аккаунтами, обменяться ID, дружба → вызов → принять.
3. В setup выбрать проверенные миссию/killzone/команды. На каждом телефоне отдельно сохранить собственные operative_count, Tac Op, предварительную основную цель и состав. Для Blades при необходимости указать все три количества аспектов.
4. До сохранения набрать заметку/состав, открыть «Последовательность игры», отметить шаг, закрыть: ввод не исчез. Повторное открытие сохраняет отметку **только на этом телефоне**; на втором она не появляется. Проверить источник, редакцию и дату.
5. Начать бой, открыть ту же панель в active; табло остаётся доступным. В Gambit TP1 на обоих устройствах тайно зафиксировать основную цель. Другой игрок до конца не должен видеть её направление. Tac Op раскрыть в указанный на карточке момент; первое начисление Tac VP также раскрывает её.
6. Провести четыре поворота. Проверить невозможность +VP поверх card cap и 6 за направление. Увеличить выведения, затем смоделировать возвращение врага кнопкой «−»: grade должен уменьшиться при переходе порога. За действия с CP отвечает игрок, автоматического начисления нет.
7. В TP4 внести начисления end of battle, проверить Crit/Tac/Kill компоненты. Первый игрок отправляет; обе основные цели раскрываются, бонус округляется вверх и появляется финальный +1 Kill VP стороне с большим grade. До finish primary bonus не начислен.
8. Второй сверяет и подтверждает: статистика/итог одинаковы с двух перспектив. Отдельно проверить dispute → reopen → исправление → повторное подтверждение. Повтор сетевого request_id не должен добавлять VP ещё раз.
9. Открыть старый матч: старые имена/очки сохранены, bonus не добавлен, неактивные справочники не доступны для новой настройки. Создать гостевую итоговую запись: VP не умножаются повторно.
10. Проверить аналитику выбранной Tac Op (включая 0 VP), историю/экспорт, затем новый backup и восстановление в отдельном тестовом экземпляре. Контролировать `docker stats`, место и возврат после перезапуска хоста.

### Исправление границ прежнего отчёта

Старая проверка config -q пропустила семантическую ошибку flow-sequence tmpfs: Docker позднее трактовал noexec как путь. Отдельная caddy validate не выявляла exec EPERM при фактическом cap_drop контейнера. Поэтому в этом отчёте ни одна из этих проверок не называется доказательством успешного Docker startup. Исправлены конфиги и добавлены регрессии, но полный **docker compose up -d --build всё ещё не выполнен в sandbox: Docker daemon отсутствует**.

### Свидетельства с реального ass-srv

Оператор прислал статусы трёх healthy контейнеров, успешный TLS с явным SNI, HTTP 200 /api/health за 0.012009 с и сообщил о регистрации двух аккаунтов с двух устройств и записи матча. После role/database jit=off и restart api сообщил «Решение сработало». Это подтверждение работы и улучшения его установки с ручными правками, не независимая сверка нового ZIP с хостом. После-замеров latency/CPU/EXPLAIN, OOMKilled=true и полного getcap не получено. Рост памяти proxy не считается подтверждённым исправлением.

В v1.1.1 заново не проводились браузерная приёмка v1.1, сверка игровых источников, full Docker build, restore на ass-srv, reboot/firewall и нагрузочный тест. Каталог остаётся прежним снимком, его будущая актуальность не заявляется. Двухтелефонную приёмку выше выполнить после обновления; точная история и команды — docs/10-developer-handbook.md и docs/11-deployment-changelog.md.
