# Воспроизводимые тесты в Docker

Сначала Docker должен работать. Запускайте без параллельной production-сборки на 4 ГБ сервере:

```sh
cd /opt/killstass
./scripts/integration-docker.sh
```

Скрипт создаёт отдельную сеть killstass-test-network, временный PostgreSQL-контейнер killstass-test-db и тестовый образ. База называется killstass_test, боевой том не монтируется, порты не публикуются. Пароль генерируется во временный env-файл 0600 и удаляется по завершении. После готовности миграций запускаются модульные и интеграционные тесты. Завершение, в том числе с ошибкой, удаляет test-контейнер с анонимным томом и сеть. Тестовые образы остаются для ускорения повторной проверки.

Если контейнер/сеть с таким именем уже существуют, скрипт отказывается их трогать. Разберите причину после прерванного запуска вручную. Для повторяемости указывайте тот же PYTHON_IMAGE, POSTGRES_IMAGE, что у поставки, через docker build args при необходимости: test-скрипт по умолчанию использует базовые теги Dockerfiles. Изолированная сеть тестов имеет egress, но никакие порты не доступны LAN.

Под Docker этот сценарий здесь не запускался; он включён как воспроизводимая инструкция. Реально выполненные проверки описаны в 07-verification.md.


## v1.1: каталог, миграция и последовательность

Штатный test-runner сохранён и расширен: копирует db и tools/catalog-import, содержит psql client (только test image, не production). Установка postgresql-client через apt внутри Debian Python test image не является инструкцией установки на ALT-хост.

Владелец выделенной test-БД в TEST_DATABASE_URL должен иметь CREATEDB для одного теста миграции. Этот тест создаёт временную UTF8 БД killstass_migration_test_<random>, применяет неизменённые 001/002, вставляет исторический подтверждённый матч, сравнивает player_results до/после 003/004 и повторяет 004. В finally временная БД удаляется. Для 002 нужен /opt/killstass/seed.json с содержимым db/legacy-seed.json (test Dockerfile уже копирует его). При запуске на ПК подготовьте этот путь либо используйте test image. Все пользовательские данные основной test-БД очищаются fixtures; production URL запрещён.

Тесты включают primary ceil 0..6/ошибки границ, Kill grade/возврат, caps по повороту и за бой, auth/ETag справки, inactive catalog/history, секретность primary/Tac, неизменность замороженных caps при импорте, finish/confirm/статистику, повторный импорт/стабильность ID, no-DDL/readonly runtime-справочники и неизменность хэшей 001/002. Без TEST_DATABASE_URL работают чистые тесты и importer dry-run, DB-тесты отмечены skipped. Браузерную приёмку на двух телефонах выполнить по docs/07-verification.md.

## Регрессии развёртывания v1.1.1

`tests/test_deployment.py` проверяет единый цитированный scalar tmpfs для каждого сервиса, сохранение cap_drop/no-new-privileges, setcap-r до USER в Dockerfile и глобальный default_sni. Для этих тестов test image дополнительно копирует docker-compose.yml и proxy/. Они статические и не заменяют реальный запуск контейнера.

Интеграционная проверка открывает новое соединение killstass_app в выделенной test-БД, ожидает SHOW jit=off и проверяет pg_db_role_setting для этой роли/БД. До теста требуется штатный db/migrate.sh, не только исполнение 001–004 вручную. Тест не меняет глобальный jit. Точные результаты повторного прогона — 07-verification.md.

## v1.9: браузерные e2e-тесты, доступность, линтер

Python-тесты (`./scripts/test.sh`, `integration-docker.sh`) не изменились по порядку запуска; добавлены `tests/test_v19.py` (трекер и автоподсчёт убийств, отмена и её конфликты, ростер соперника до/после старта, импорт `.ros`/`.rosz` и защита от XML-бомб, турниры: швейцарская система без повторов, лига, bye, ручной результат, права; Elo, статистика часов, страница администратора и запрет роли приложения менять `is_admin`; health и единый источник версии).

Фронтенд проверяется отдельно, Node.js нужен только на машине разработчика или в тестовом контейнере:

```sh
npm ci                      # версии закреплены в package.json и package-lock.json
npm run lint                # ESLint (web/, tests/e2e/) + prettier --check
npm run test:unit           # node:test: калькулятор атаки и QR-кодировщик, без браузера и сервера
E2E_BASE_URL=http://localhost:8000 npm run e2e    # Playwright + axe-core против запущенного сервера
E2E_CHROMIUM=/usr/bin/chromium npm run e2e        # свой Chromium вместо скачанного Playwright
E2E_ADMIN=1 node --test tests/e2e/admin.test.mjs  # если e2e-alpha уже администратор этой БД
```

`npm run e2e` запускает `tests/e2e/*.test.mjs` последовательно (`--test-concurrency=1`). Адрес должен быть безопасным контекстом (`https://` или `http://localhost`): cookie сессии — `Secure`. Тесты создают аккаунты `e2e-alpha`/`e2e-bravo` (пароль `E2E_PASSWORD`, по умолчанию тестовый) и их данные — **только против тестовой БД**, не против боевого сайта. Каждая страница проверяется axe-core (`wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`) в светлой и тёмной теме; тест падает при нарушении доступности, ошибке JS в консоли, нарушении CSP, ответе 5xx или горизонтальной прокрутке на телефоне (390 px). Тесты ростеров нуждаются в справочнике команд и без него пропускаются.

Воспроизводимый вариант в Docker — `./scripts/e2e-docker.sh`: сеть `killstass-e2e-network` (internal, без выхода наружу и портов), временные `killstass-e2e-db` (БД `killstass_e2e`, случайный пароль во временном env-файле 0600) и `killstass-e2e-api` (read-only, cap-drop ALL, `APP_ORIGIN=http://localhost:8000`), образ тестов `tests/e2e/Dockerfile` на `mcr.microsoft.com/playwright`. Браузер запускается в сетевом пространстве API (`--network container:killstass-e2e-api`), поэтому приложение для него — `http://localhost:8000`. `E2E_TEAMS_BUNDLE=путь/teams-bundle.json` сначала загружает справочник (как `import-teams.sh`), тогда выполняются и тесты ростеров; v1.11: `E2E_RULES_BUNDLE=путь/rules-bundle.json` — общие правила (как `import-rules.sh`), тогда `v111.test.mjs` проверяет и поиск правил оружия. После основного прогона владелец временной БД делает `e2e-alpha` администратором и повторяет `admin.test.mjs` с `E2E_ADMIN=1`. По завершении (и при ошибке) контейнеры, анонимные тома и сеть удаляются; при совпадении имён скрипт отказывается работать. Для сборки образа тестов нужен доступ к `mcr.microsoft.com` и npm; на ass-srv этот сценарий не запускался.

Ограничение частоты: вход — 15 попыток за 15 минут с IP, регистрация — 5. При частых локальных прогонах на одной тестовой БД очистите `DELETE FROM rate_limits` от имени владельца тестовой БД.
