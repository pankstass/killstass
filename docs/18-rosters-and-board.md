# 18. Табло в стиле BattleKit, правила фракций и конструктор ростеров (v1.8.0)

## Табло матча

Идущий и завершённый матч показываются одним «табло» (`web/board.js`) вместо прежних карточек игроков и счётчиков. Оформление по мотивам BattleKit, графика и тексты BattleKit/GW не копировались.

- **Верхняя полоса**: «Ход», общий счёт `X – Y` цветами игроков, повороты 1…N (★ и буква — у кого инициатива), «Конец» (открывает «Завершить игру» / «Подсчитать итог») и меню **«Функции»**.
- **«Функции»**: демо-матч, «Поменять местами» (только на этом устройстве), настройки часов, кубики, условия Crit Op, инициатива, «Завершить игру»; после завершения — «Поделиться результатом». Открытый раздел появляется листом под полосой, закрывается × или повторным выбором; меню закрывается Esc и щелчком мимо.
- **Половины игроков**: игрок 1 — красная, игрок 2 — синяя (на телефоне друг под другом, от 1180 px — рядом). В шапке — эмблема (первая буква команды), имя, команда (ссылка на датакарты), VP крупно.
- **Сетка поворотов** (Approved Ops 2025): строки Crit и Tac — «черепа» по числу доступных очков в повороте (лимиты замороженной миссии и своей Tac Op); нажатие на n-й череп ставит n VP в этом повороте, повторное — снимает. Повороты без очков заштрихованы. Если лимитов нет (Tac Op соперника на общем экране hot-seat ещё скрыта) — обычный счётчик −/+. Строка Kill — 5 черепов Kill grade и отдельный череп бонуса «больше уничтожено, чем у соперника» (пунктир, пока игра идёт).
- **Низ половины**: CP (+/−), Tac Op (скрыта / раскрыть) и основная операция (выбор и фиксация только в TP1), «Оперативников врага» с числом уничтоженных моделей (+/−), строка Crit / Tac / Kill / основная, заметки к повороту.
- **Часы** — между половинами: у каждого игрока своё время и шестиугольная кнопка (запустить / передать ход), в центре общее время, режим и пауза. Если часы не включены — кнопка «Включить часы».
- Старые матчи (не Approved Ops) — строки по источникам VP со счётчиком в текущем повороте; гостевые записи — только итоговые VP.
- Таблица очков по поворотам, заметки, составы и история изменений — свёрнутыми блоками под табло.

Ничего не считается «для протокола» на клиенте: нажатия отправляют те же запросы, что и раньше (`/scores`, `/cp`, `/kills`, `/primary`, `/reveal-tac`, `/actions`, `/clock`), проверяет сервер. API счёта не менялся.

## Правила фракции — все варианты

В v1.7 правила вида «выберите одну из опций» (Chapter Tactics, Blessings of Khaine, Warpcoven и др.) показывались без вариантов, а склеенные распознаванием строки ломали текст. Теперь импорт сохраняет у правила массив `options[{name, body}]`, страница «Правила фракции» показывает каждый вариант отдельным блоком. Если текст правила взят из BSData (в kt-datacards его нет или он искажён), рядом стоит метка `BSData`. Формат пакета — `killstass-teams/2` (пакеты `/1` по-прежнему принимаются, но без вариантов и схем ростеров).

На наборе kt-datacards `042e924` + BSData `30c48ce`: 14 команд с вариантами (до 16 вариантов у Blades of Khaine). У Strike Force Variel правил фракции нет в обоих источниках.

## Конструктор ростеров

Раздел **«Ростеры»** в меню (`#rosters`), кнопка «Собрать ростер» на странице команды. Похоже на New Recruit / BattleScribe, но работает в LAN без внешних сервисов.

- Список своих ростеров (до 100 на пользователя): команда, число оперативников, «корректен» / «ошибок: N», пометка «данные обновились».
- Редактор (`#rosters/{id}`): слева список оперативников команды «+ добавить» (на телефоне — компактные кнопки), справа карточки выбранных: номер, своё имя оперативника, характеристики APL / MOVE / SAVE / WOUNDS, оружие с профилями, выбор вариантов: группа «одно из» — переключатели, необязательные — флажки, количество — −/+; обязательные показаны галочкой. «Снаряжение и прочее» — отдельные записи каталога. Дублировать / убрать оперативника, заметки.
- Проверка сразу при каждом изменении (на сервере): сводка «Ростер корректен / Есть ошибки», счётчики ограничений (например `Operative 8/9`, `Leader 1/1`), сообщения у карточек и в сводке (минимум/максимум, недоступная позиция, предупреждения каталога, «снаряжения больше 4»).
- Автосохранение через 0,7 с после правки; конфликт версий (две вкладки) — загрузка свежей версии с уведомлением.
- **Экспорт**: текст (для поля «состав» матча и мессенджеров), `.ros` / `.rosz` для BattleScribe и New Recruit, JSON.
- **В матче**: в подготовке (и в форме гостя hot-seat) — «Ростер из конструктора». Выбор подставляет команду, число оперативников и текст состава; у участника сохраняется ссылка `roster_id`. Ростер чужой команды не принимается (`roster_team_mismatch`), ростеры других игроков не видны (`roster_id` соперника в ответе матча скрыт). При удалении ростера у матча остаётся текст состава.

### Откуда схема

`scripts/import-teams.sh` при сборке пакета компилирует для каждой команды `2024 - *.cat` + `2024 - Kill Team.gst` из BSData в компактную **схему ростера** (`roster_schema`, в `team_data`, ≤2 МБ, у самых больших ≈0,2 МБ): дерево позиций (оперативники, группы выбора, оружие, снаряжение), категории и ограничения силы, условия и модификаторы, профили и правила. `roster_hash` — SHA-256 схемы; если после нового импорта он изменился, ростер помечается «данные обновились», устаревшие позиции — ошибкой «позиции больше нет».

Поддерживаемое подмножество BattleScribe (всё, что используют каталоги Kill Team): ограничения min/max по selections с областями parent/self/force/roster/предок/категория, shared и includeChildSelections; ограничения категорий силы; модификаторы set/increment/decrement/append ограничений, hidden, name, категорий, add error/warning; условия, группы условий, repeats. Очки (costs) не учитываются — в Kill Team 2024 их нет. На 48 командах с данными BSData схема собирается, эталонный ростер Kommandos проходит проверку; у Exodite Dragon Masters в BSData нет каталога — для неё конструктор недоступен.

### Формат ростера

```json
{"selections": [{"uid": "a1b2c3d4", "key": "e-boss/…", "n": 1, "name": "Гроцник",
                 "sel": [{"uid": "…", "key": "…", "n": 1, "sel": []}]}],
 "notes": "…"}
```

`uid` — `^[a-z0-9]{6,16}$`, уникален; `key` — путь позиции в схеме (≤300 символов); `n` — 1…99; `name` ≤80; глубина ≤8, всего ≤500 выборов, документ ≤256 КБ. Нарушения структуры — 422 с кодами `roster_invalid`, `roster_format`, `roster_too_deep`, `roster_too_large`, `roster_bad_uid`, `roster_bad_key`, `roster_bad_number`, `roster_bad_name`, `roster_schema_unsupported`. Нарушения правил набора не мешают сохранению — они попадают в `summary`.

### API

| Метод и путь | Ответ |
|---|---|
| GET /teams/{slug}/roster-schema | `{slug,name,catalog_id,hash,schema}`; ETag = `roster_hash`, 304; 404 `roster_schema_missing` |
| GET /rosters | `{rosters:[{id,team_slug,team_name,catalog_id,name,version,updated_at,valid,operatives,errors,stale}], teams:[{slug,name,catalog_id}], limit}` |
| POST /rosters | `{request_id, team_slug, name, data?}` → ростер (идемпотентно по request_id); 409 `roster_limit` |
| GET /rosters/{id} | `{id,team_slug,team_name,catalog_id,name,data,summary,version,stale,…}`; чужой/нет — 404 `roster_not_found` |
| PUT /rosters/{id} | `{version,name,data}` → новая версия и `summary`; 409 `version_conflict` |
| DELETE /rosters/{id} | тело `{}` → `{ok:true}` |
| GET /rosters/{id}/export?format=text\|json\|ros\|rosz | файл; имя с кириллицей — `filename*=UTF-8''…` |
| PUT /matches/{id}/setup, PUT /matches/{id}/player-setup | новое необязательное поле `roster_id` (null — отвязать); 422 `roster_not_found`, `roster_team_mismatch` |

`summary = {valid, errors[], warnings[], operatives, limits[{name,count,min?,max?}]}`, сообщение — `{level, code, uid, params}`; коды `min`, `max`, `category_min`, `category_max`, `unknown_entry`, `hidden`, `catalogue`, `equipment`, `no_schema` переводит клиент (`rosterIssue_*`).

Лимит тела запроса: 256 КБ для `/api/rosters*` (Caddy и приложение), 32 КБ для остального.

### БД — `010_rosters.sql`

- `team_data`: `roster_schema jsonb`, `roster_hash text` (64 hex). Пишет владелец БД при импорте, приложение только читает.
- `rosters`: `id uuid`, `user_id` → users ON DELETE CASCADE, `team_slug`, `name` 1–80, `data jsonb` (≤256 КБ), `schema_hash`, `summary jsonb`, `version`, `created_at`, `updated_at`; индекс `(user_id, updated_at DESC)`. Роль приложения — SELECT/INSERT/UPDATE/DELETE.
- `match_players.roster_id` → rosters ON DELETE SET NULL.

Миграция append-only, health ожидает 10 миграций. После обновления выполните `./scripts/import-teams.sh`, иначе варианты правил и конструктор будут пустыми (страница подскажет команду).
