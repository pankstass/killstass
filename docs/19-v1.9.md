# 19. v1.9.0 — трекер оперативников, калькулятор атаки, турниры, администрирование, e2e-тесты

Сводка выпуска: что появилось у игроков, у оператора сервера и у разработчика. API и БД — в конце документа; порядок обновления — `UPDATE-INFO.md`.

## Для игроков

### Трекер оперативников

Под половиной каждого игрока на табло — список оперативников (`web/tracker.js`, `api/tracker.py`).

- **Откуда берутся**: при старте матча — из ростера, привязанного в подготовке (оперативники с выбранным оружием); пока трекер пуст, то же делает кнопка «Заполнить из ростера»; вручную — «Добавить оперативника»: имя с подсказками по датакартам своей команды (характеристики и оружие подставятся из справочника) или своё имя и число ран. До 40 на игрока.
- **На карточке**: раны (−/+) и отметка «Ранен» (меньше половины ран), череп «Вывести из строя», приказ Engage/Conceal, «Активирован» в текущем повороте, имя открывает датакарту. Выведенный оперативник зачёркнут, его кнопки выключены.
- **Убийства считаются сами**: оперативник с 0 ран добавляет убийство сопернику в текущем повороте (Approved Ops 2025, TP 1–4), возвращённый в строй или удалённый — снимает. Число «Оперативников врага» на табло помечается «считается по трекеру»; ручные −/+ остаются для матчей без трекера.
- Половина соперника — только для чтения; изменения приходят на второй телефон сразу (SSE-событие `tracker`). Частые нажатия не меняют `matches.version`, поэтому не вызывают `version_conflict` у соперника.

### Отменить последнее действие

Кнопка «Отменить» на полосе табло возвращает **своё** последнее изменение: очки VP, CP, убийства, инициатива, поворот, трекер. Подсказка на кнопке показывает, что именно будет отменено. Соперник чужие действия отменить не может; если после вашего изменения то же значение уже поменялось, сервер отвечает `undo_conflict` (ничего не меняется). Отмена пишется в историю изменений матча. Только для идущего матча.

### Датакарты и ростер соперника

Меню «Функции» → «Ростеры»: свой ростер — всегда, ростер соперника — после старта (до старта 403 `roster_hidden`, чтобы не раскрывать состав). Нажатие на имя оперативника открывает датакарту: характеристики, оружие с профилями, способности. Из листа ростера можно отправить его на печать.

### Импорт ростеров BattleScribe / New Recruit

«Ростеры» → «Импорт»: файл `.ros` (XML) или `.rosz` (zip). Команда определяется по каталогу в файле (id, затем имя), если не нашлась — появится выбор команды. Позиции сопоставляются со схемой ростера по пути BattleScribe, затем по id и по имени; нераспознанные пропускаются и перечисляются после импорта. Результат проверяется как обычное сохранение — ошибки можно исправить в конструкторе. Ограничения: файл до 700 КБ, XML до 4 МБ, `DOCTYPE`/`ENTITY` отклоняются; лимит 100 ростеров на аккаунт.

### Калькулятор атаки

«Функции» → «Атака» (`web/attackcalc.js` — чистые функции, `web/attack.js` — лист на табло). Атакующий — свой оперативник (оружие из датакарты) или ручной профиль; цель — оперативник соперника/свой или ручные SAVE и раны; флажки «Укрытие», «Затенён» (Obscured), «Атакующий ранен».

- Правила оружия Kill Team 2024: Accurate, Balanced, Ceaseless, Relentless, Lethal, Severe, Rending, Punishing, Brutal, Piercing, Piercing Crits, Saturate, Devastating; укрытие (один успех защиты засчитывается без броска — кубиков защиты на один меньше; не действует против Saturate), Obscured (критические успехи становятся обычными, один успех отбрасывается), раненый атакующий (попадание на 1 хуже: 3+ → 4+). Защитник распределяет спасброски так, чтобы получить меньше урона. Неизвестные калькулятору правила оружия перечисляются как «Не учтено».
- **Бросок**: кубики атаки и защиты (переброшенные показаны зачёркнутыми), распределение спасбросков, итоговый урон. **Ожидание**: 20 000 смоделированных атак с фиксированным зерном (числа не «прыгают» между открытиями) — средний урон, шанс нанести хоть какой-то урон и вывести цель из строя, средние криты/обычные попадания и спасброски, гистограмма урона (столбцы от числа ран цели выделены). Точный перебор (`resolve`) используется в тестах для проверки симуляции.
- «Применить урон» снимает раны у цели в трекере — только если вы можете менять этого оперативника (своя половина или hot-seat). Ближний бой — без парирований: только успехи и урон.

### Статистика

- **Ростеры**: игры, победы/ничьи/поражения и средняя разница VP по каждому ростеру, с которым вы играли.
- **Время по часам** (последние 300 партий с часами): средняя и самая долгая партия; для шахматных часов и обратного отсчёта — сколько в среднем тратите вы и соперник.
- **Рейтинг Elo среди друзей**: подтверждённые дружеские матчи внутри круга «вы + принятые друзья» (в том числе между самими друзьями), по порядку игр; старт 1500, K = 32, ничья — 0,5; пересчитывается при каждом открытии.

### Турниры в LAN

Пункт меню «Турниры» (`#tournaments`): организатор выбирает формат — **швейцарская система** (число туров задаётся, 1–30, или ⌈log₂ N⌉) или **лига** (каждый с каждым по кругу: N − 1 туров, при нечётном N — N), участников — себя, принятых друзей и гостей по имени (2–32).

- «Начать» — пары первого тура (в швейцарской системе — случайный порядок) с номерами столов; при нечётном числе один участник получает bye — победа с 0 VP. Результат пары: из матча, открытого кнопкой «Матч» (с другом — обычный матч, с гостем — hot-seat), после его подтверждения; или вручную — организатор либо игрок пары в текущем туре. Ручной результат главнее.
- «Следующий тур» — когда у всех пар есть результат. Швейцарская система сводит соседей по таблице без повторных встреч (перебор с возвратом; если без повтора нельзя — соседей подряд), bye — нижнему в таблице, у кого его ещё не было. Участника можно снять: дальше он не получает пар (в лиге его соперник получает bye).
- Таблица: очки 3/1/0, затем VP, разница VP, сила соперников, номер посева. «Завершить» фиксирует итог.
- Друзьям приходят уведомления «Вас добавили в турнир» и «Матч турнира». До 10 незавершённых турниров у организатора.

### QR-код приглашения

Экран ожидания соперника показывает QR-код ссылки-приглашения: второй игрок наводит камеру и сразу попадает в матч. Кодировщик свой (`web/qr.js`, QR Model 2, byte mode, версии 1–40, уровни L/M/Q/H), без сети и библиотек; результат — SVG.

### Печать ростера

Кнопка «Печать» на странице ростера и в листе ростеров матча: только карточки оперативников, по две в ряд на A4, без интерфейса (`@media print`, `#print-root`; на экране ничего не меняется).

### Табло и вид

- **Демо** (`#demo`) теперь на том же табло, что и настоящий матч: очки, CP, убийства, трекер, отмена, кубики и калькулятор, завершение с итоговой таблицей Crit/Tac/Kill/основная операция, «Вернуться» и сброс — всё на устройстве, на сервер ничего не отправляется (часов и ростеров в демо нет).
- **Режим стола** («Функции» → «Режим стола»): телефон лежит между игроками, половины идут одна под другой, верхняя (и её сторона часов) повёрнута на 180° — к сидящему напротив; какая сверху, меняет «Поменять местами». Запоминается на устройстве.
- **Отклик нажатий**: изменившиеся VP коротко «подпрыгивают», нажатая кнопка слегка сжимается, на телефонах с вибромотором — короткая вибрация в трекере; при «уменьшить движение» в системе анимации отключены.
- **Эмблемы команд**: шестиугольник в цветах семейства фракций с символом архетипа — собственная геометрия, без символики GW (`web/emblem.js`).
- **Доступность**: проверка axe-core (WCAG 2.1 A/AA) на всех экранах в обеих темах; контраст бейджей и баннеров, видимая рамка фокуса, подписи кнопок совпадают с видимым текстом, прокручиваемые таблицы доступны с клавиатуры.

## Для оператора сервера

### Страница администратора (`#admin`)

Видна только аккаунтам с `users.is_admin`. Выдаёт и снимает права только владелец БД:

```sh
./scripts/admin.sh list            # администраторы
./scripts/admin.sh grant LOGIN     # дать доступ к #admin
./scripts/admin.sh revoke LOGIN    # забрать
```

Роль приложения не может изменить флаг: с v1.9 у неё нет `UPDATE/INSERT` на `users`, кроме колонок регистрации, имени и пароля (`db/migrate.sh`). На странице: версия и миграции, число пользователей, сессий, ростеров, турниров, команд справочника, размер БД, матчи по статусам, последняя загрузка справочника; **отзывы** (новые/все, «Обработано»/«Вернуть»); **поиск пользователей** (логин, имя, ID; число матчей и ростеров, последний вход). `scripts/feedback.sh` удалён — его заменяет эта страница.

### Обновление с проверками

`scripts/update.sh` теперь вызывает `scripts/smoke.sh`:

- `--pre` — после сборки, пока старая версия работает: `docker compose config`, `caddy validate` нового Caddyfile внутри нового образа proxy. Ошибка — обновление останавливается, сайт не затронут.
- `--post` — после запуска: `/api/health` (статус, версия = `VERSION`, число миграций), `schema_migrations` в PostgreSQL, версия на странице и загрузка версионированной статики через Caddy.

Скрипт можно запускать вручную в любой момент.

### Единый источник версии

Номер версии записан только в `VERSION`. API читает его при старте (`/api/health` → `version`, `migrations`; OpenAPI), сервер подставляет его в `index.html`, статика отдаётся по адресам `/static/v/<версия>/…` — Caddy кеширует их на год (`immutable`), после обновления браузер гарантированно получает новые файлы. `package.json` и `docs/openapi.json` сверяет тест.

### Caddy

- `/api/rosters/import` — тело до 1 МБ (base64 файла), остальные `/api/rosters*` — 256 КБ, прочее — 32 КБ (матчеры не пересекаются).
- `/static/v/*` — `Cache-Control: public, max-age=31536000, immutable`; прочая `/static/*` — час, как раньше.

## Для разработчика

### Фронтенд: ES-модули

`web/index.html` подключает один модуль `web/main.js`; код разбит на модули с явными `import`/`export` (без глобальных переменных): `core` (API, i18n, состояние), `app` (маршрутизация и экраны), `board`, `turns`, `clock`, `tracker`, `attack`/`attackcalc`, `sheets` (датакарты и печать), `rosters`, `teams`, `tournaments`, `admin`, `demo`, `styleguide`, `qr`, `emblem`, `dice`, `share`, `quickstart`, `reference`, `ops`. Обработчики регистрируются в `main.js` в прежнем порядке. Неиспользуемые правила CSS удалены (снимки DOM, вычисленных стилей и размеров ключевых экранов до/после совпали).

### Витрина компонентов (`#styleguide`)

Без входа: цвета и токены обеих тем, типографика, кнопки, бейджи, поля форм, иконки, эмблемы, половина табло, датакарты, QR и пример печати. Удобно проверять правки CSS и доступность.

Только для разработки (в образах приложения Node.js нет). Node 22+ (тест-раннер `node --test` с шаблонами путей):

npm run lint           # ESLint (web/, tests/e2e/) + prettier --check

ESLint: `eslint.config.js` (рекомендованные правила, `prefer-const`, `no-var`, `eqeqeq`, запрет `eval`/`new Function`, запрет неявных глобальных).

### Тесты в браузере и доступность — `tests/e2e`

- `unit.test.mjs` — калькулятор атаки (каждое правило оружия, распределение спасбросков, точный расчёт против независимого перебора, сходимость симуляции) и QR-кодировщик (служебные узоры, формат и версия, эталонные символы, проверенные декодером OpenCV, ёмкость и маски). Без браузера и сервера: `npm run test:unit`.
- `demo.test.mjs` — без аккаунта: экран входа (ошибка пароля, телефон 390 px, обе темы), демо (счёт, CP, трекер с автоподсчётом убийств, отмена, калькулятор, режим стола, завершение, сброс), витрина и печать.
- `app.test.mjs` — два игрока в двух контекстах браузера: приглашение по ссылке и QR (SVG сверяется с `web/qr.js`), трекер и SSE, отмена только автором, права калькулятора, подтверждение, история, Elo, ростеры (экспорт `.ros`/`.rosz`, импорт обратно, автозаполнение трекера, датакарты, печать — пропускается без справочника), турнир, все экраны в обеих темах, CSRF.
- `admin.test.mjs` — обычный аккаунт: нет пункта меню, пояснение, 403 от API; администратор: сводка, отзывы, поиск (пропускается без прав; `E2E_ADMIN=1` делает обязательным).

Каждая страница проверяется axe-core (`wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`); тест падает при любом нарушении, ошибке JS, нарушении CSP или ответе 5xx. Аккаунты `e2e-alpha` и `e2e-bravo` создаются при первом запуске, потом используется вход (сессия хранится в `test-results/e2e-auth/`).

```sh
# против запущенного сервера (адрес — безопасный контекст: https:// или http://localhost)
E2E_BASE_URL=http://localhost:8000 npm run e2e
E2E_CHROMIUM=/usr/bin/chromium npm run e2e      # свой Chromium вместо скачанного Playwright

# всё в Docker: временные БД и API во внутренней сети, Chromium из mcr.microsoft.com/playwright
./scripts/e2e-docker.sh
E2E_TEAMS_BUNDLE=/root/teams-bundle.json ./scripts/e2e-docker.sh   # со справочником — и тесты ростеров
```

`scripts/e2e-docker.sh` не трогает боевые контейнеры, тома и порты; браузер работает в сетевом пространстве временного API (`http://localhost:8000`), после основного прогона владелец временной БД выдаёт `e2e-alpha` права администратора и запускает `admin.test.mjs` с `E2E_ADMIN=1`. Для сборки образа тестов нужен доступ к `mcr.microsoft.com` и npm. Сервер ограничивает вход (15 за 15 минут с IP) и регистрацию (5): при частых локальных прогонах на тестовой БД помогает `DELETE FROM rate_limits`.

## БД — `011_tracker_tournaments.sql`

- `users.is_admin boolean NOT NULL DEFAULT false`.
- `match_operatives`: оперативники матча (`player_id` → match_players, `position` 1–40, имя, датакарта, `stats`/`weapons` jsonb ≤16 КБ, раны, приказ, `activated_tp`, `incapacitated_tp`; `wounds = 0` ⇔ `incapacitated_tp` задан). Каскад при удалении матча.
