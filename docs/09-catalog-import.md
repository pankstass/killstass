robots.txt Wahapedia допускает `/kill-team3/`; файл BattleKit вернул 404, что само по себе не является разрешением на любое использование. Чтение с понятным User-Agent, 3-секундными паузами при исследовании и кэшем; поставляемый загрузчик использует не менее 5 секунд между HTTP-запросами. Повторная выгрузка кэш не обходит. Любые новые ограничения/условия сайта означают остановку автоматической загрузки и переход к ручному сохранению с допустимым использованием. Юридическая экспертиза не проводилась.

## 4. Механика подсчёта

- Максимум 6 VP Crit, 6 VP выбранного Tac Op, 6 VP Kill Op до primary-бонуса; максимум итога 21. Одна Tac Op на игрока, из разрешённого архетипа.
- `per_turn_caps` — безопасные верхние границы, выведенные из опубликованных условий карточки и общей шестёрки; это не обещание, что любое такое значение достижимо в конкретной позиции. Например Secure [0,2,2,2], Dominate [0,0,3,3], Rout [2,2,2,2]. Лимиты, требующие проверки позиции, действий, раскрытия и контроля, контролируют игроки по карточке. Это журнал, не автоматический судья настольной игры.
- Начисления «end of battle» записываются в TP4 соответствующего направления до finish. Для Energy Cells/Download/Data/Steal Intelligence/Retrieval TP4 включает эти начисления; отдельно проверяется суммарный cap 6.
- Primary bonus = ceil(component / 2); не половина общего счёта и не умножение на 1.5 каждого направления. До finish бонус в итог не включён.
- Kill grade по текущему числу выведенных врагов и исходному засчитываемому составу:

| Состав | grade1 | grade2 | grade3 | grade4 | grade5 |
|---:|---:|---:|---:|---:|---:|
|5|1|2|3|4|5|
|6|1|2|4|5|6|
|7|1|3|4|6|7|
|8|2|3|5|6|8|
|9|2|4|5|7|9|
|10|2|4|6|8|10|
|11|2|4|7|9|11|
|12|2|5|7|10|12|
|13|3|5|8|10|13|
|14|3|6|8|11|14|

Kill VP = grade; в конце ещё 1 VP стороне с большим grade. Возврат выведенного оперативника уменьшает текущий счётчик и может уменьшить grade/VP; используйте отрицательную поправку. Игнорируемых правилами команды для Kill Op оперативников не включайте ни в исходное число, ни в выведения. Неизвестные количества вне таблицы 5–14 блокируют старт, а не получают выдуманные пороги.

## 5. Обновление — безопасный конвейер

Все команды на **ПК владельца** из корня полного репозитория. Python 3.12+, только стандартная библиотека. Не устанавливать инструменты импорта в production-образ/на ass-srv. .env/учётные записи/пароли здесь не нужны.

### Получить один публичный HTML или сохранить вручную

```sh
python3 tools/catalog-import/import_catalog.py \
  --fetch-url https://wahapedia.ru/kill-team3/the-rules/approved-ops-2025/ \
  --cache catalog-cache
```

Загрузчик сначала проверит robots, кэширует HTML и metadata JSON, не выполняет скрипты. Он не обходит CAPTCHA, не авторизуется и не обращается к внутренним POST. 403/429/ошибка robots — остановиться, не повторять циклически. Кэш намеренно не имеет авто-refresh: для новой проверенной даты создайте отдельный каталог кэша. Во время записи действуют лимит 4 MB и timeout 30 s.

Ручной вариант: браузер → сохранить **отрендеренную нужную вкладку**, записать фактическое время получения с часовым поясом и видимую версию, положить в `catalog-cache/manual/`. Для полного обновления нужны:

1. BattleKit: Game Sequence, Approved Ops (каждая Crit Op), Tac Ops (каждая карточка), список команд с архетипами, команда Strike Force Variel, спорная Sweep & Clear. Если «Сохранить страницу» не содержит загруженную вкладку, сохраните её DOM после загрузки/печатную версию, не только пустую оболочку сайта.
2. Wahapedia: Approved Ops 2025 вместе с публичными HTML-массивами карточек; Core Rules; при изменениях — страницы нужных команд с Books/Archetype; отдельно таблица KillGrade.png для визуальной сверки. Адреса всех исходных страниц — sources.json.
3. Для новых схем — страница с явными названиями/номерами; Community Maps пока не импортировать без понятных условий использования.

### Извлечь кандидатов — они всегда неактивны

```sh
python3 tools/catalog-import/extract_saved.py catalog-cache/manual/approved.html \
  --adapter approved \
  --url https://wahapedia.ru/kill-team3/the-rules/approved-ops-2025/ \
  --retrieved-at 2026-10-26T15:00:00+00:00 --version 'УКАЖИТЕ ВИДИМУЮ ВЕРСИЮ' \
  --output candidates.json
```

Дата выше — пример формата, замените фактической датой файла, не текущей датой для старого сохранения. Адаптер `--adapter team` создаёт кандидата по сохранённой странице команды. Если структура изменилась, адаптер останавливается, а не гадает. Для BattleKit специального парсера недокументированного API нет: редактор переносит факты из разрешённой сохранённой вкладки в review-template.json. Его две реальные спорные записи уже имеют active=false; это рабочие данные для проверки, а не выдуманный игровой контент.

Проверка редактора: удалить review_excerpt из распространяемого seed, написать короткий RU-пересказ, сохранить EN, архетип, момент раскрытия, caps по всем четырём поворотам, источник/дату/версию/hash, отметить конфликты. Только подтверждённым записям выставить verification=verified и active=true; сомнения остаются unverified/conflict и false. Стабильные коды не менять; префикс `2024-wahapedia-...` или `2024-battlekit-...`. Не создавать второй code для одного объекта только из-за смены источника: обновите provenance существующего объекта после проверки.

### Нормализовать, сравнить, сформировать новую миграцию

```sh
# reviewed.json — полный проверяемый снимок разделов; схема как db/seed.json.
python3 tools/catalog-import/import_catalog.py --input reviewed.json \
  --baseline db/seed.json --dry-run
python3 tools/catalog-import/import_catalog.py --input reviewed.json \
  --baseline db/seed.json --output catalog-output --migration 005_catalog_update.sql
```

В output: seed.json, SQL с UPSERT по code, report.json с added/changed/unchanged/deactivated/unverified/conflicts/steps и ссылками. dry-run ничего не пишет и не загружает. Валидация не даёт активировать unverified/conflict, пропустить provenance, изменить kind/edition прежнего code при заданном baseline, импортировать произвольный source URL, пропустить caps или сделать ручной Kill VP для Approved Ops.

Исчезнувшее выключается **только при явно полном разделе**:

```sh
python3 tools/catalog-import/import_catalog.py --input reviewed.json --baseline db/seed.json \
  --complete-scope wahapedia:2024:mission:approved2025 \
  --complete-scope wahapedia:2024:tac_op:approved2025 \
  --complete-scope wahapedia:2024:sequence:approved2025 \
  --output catalog-output --migration 005_catalog_update.sql
```

Пустой «полный» раздел отклоняется. Без complete-scope отсутствующие коды остаются как были; явно переданная inactive-запись выключается всегда. Старые матчи продолжают ссылаться на существующие ID. Полный порядок Game Sequence должен быть без дубликатов; порядок уникален только среди активных шагов. Импорт временно выключает входящие шаги внутри транзакции и затем обновляет их, что позволяет перестановки без удаления старых записей. Если новый code занимает позицию исчезнувшего, для соответствующего полного источника/редакции нужен complete-scope, иначе конфликт уникальности остановит импорт. Это справка, чек-лист старой версии локален и не переносится автоматически.

Проверьте SQL/отчёт, затем поместите seed.json в db/seed.json и новый SQL в db/migrations/. Начальная 004 воспроизводится тем же инструментом с `--input db/seed.json --migration 004_verified_catalog.sql` (не применяйте как новую на рабочем сервере). 001/002/003/004 после применения больше не редактировать. Обновить SHA256SUMS, выполнить тесты и scripts/update.sh. Мигратор выполняет транзакцию и выдаёт runtime-роль без DDL, справочники только SELECT. Не запускать новый SQL от killstass_app.

## 6. Работа в LAN и ограничения

Панель получает JSON один раз через авторизованный API, использует ETag версии и локальный кэш, а не обращается из браузера к источникам. Поэтому внешний интернет во время игры не нужен. Это не офлайн-синхронизация матча при отключённом Wi-Fi/сервере: команды счёта требуют API. Кэш справки можно показать при кратком отказе её API; дата всегда видна. Отметки локальны по UUID матча + edition + ETag и не влияют на других игроков/старт.

Faction Rules — только внешние ссылки; картинки карт, чужая графика и полные тексты фракций не включены. Для внешних ссылок интернет понадобится отдельно. Полноценные исключения каждой команды и автоматическая проверка позиции/действий — вне объёма журнала; игроки сверяют их по источнику.
